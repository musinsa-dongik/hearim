# 헤아림 대외용 학습 노트 템플릿

데일리(내부용) 작성 후, 같은 내용을 대외용으로 변환한다.

## 변환 원칙

### 제거 대상
- Jira 티켓 번호 (GPRD-xxxx, PROJ-xxxx 등)
- Git 커밋 해시 (`68fd9f3d6` 등)
- 줄 수, 파일 수 (`13개 파일, +772/-103줄` 등)
- 내부 서비스명, 프로젝트명, 팀명
- 내부 컴포넌트/함수명은 일반화 (ReviewGalleryFilter -> LegacyFilter 등)

### 유지 대상 (핵심)
- **"내가 부딪힌 문제 -> 시도 -> 발견" 서사**
- 판단 근거, 트레이드오프, 반례
- 코드 패턴 (일반화된 형태)
- 공식 문서 링크

### 톤 규칙: "정적 설명" 금지

교과서적 서술 대신, 경험 기반 서사로 작성한다.

**금지 (정적):**
> `storage` 이벤트는 같은 탭에서의 변경은 감지하지 못한다.

**권장 (경험 기반):**
> 토글 버튼을 눌렀는데 UI가 안 바뀌어서 당황했다. `addEventListener('storage', ...)`를 썼는데, 이 이벤트가 같은 탭에서는 안 먹는다는 걸 몰랐다. 그래서 커스텀 listener를 직접 관리하는 방식으로 바꿨고, 이게 결국 useSyncExternalStore의 subscribe 패턴과 같은 구조였다.

**판별 기준:** "이 문장을 GPT/Claude에게 물어봐도 같은 답이 나오는가?" -> YES이면 정적 설명이므로 내 경험으로 바꿔야 한다.

## 템플릿

```markdown
## 학습 노트: [주제를 관통하는 제목]

### 배경

[대외비 없이 1-2문장으로 상황 설명. "기존 UI를 새 UI로 점진 전환하는 작업에서..." 수준]

---

### 1. [개념명]: [내 경험과 연결한 부제]

[문제 상황 -> 시도 -> 발견 순서로 서술. 3-5문장.]
[왜 이 방법을 택했는지, 대안은 뭐였는지, 그 대안을 왜 안 택했는지.]

**코드:**
```typescript
// Before: 뭐가 문제였는지 주석으로 설명
// After: 어떻게 바꿨는지
```

**언제 쓰는가 / 언제 안 쓰는가:**
- 적용 조건
- 반대로 맞지 않는 경우

> 참고: [공식 문서 또는 권위 있는 레퍼런스 링크]

---

### 2. [개념명]: [부제]

[동일 구조. "내가 부딪힌 문제"로 시작.]

---

### 정리

| 상황 | 판단 기준 | 선택 |
|------|----------|------|
| ... | ... | ... |

### 더 알아볼 것

- [ ] [구체적 질문]
- [ ] [구체적 질문]

### 참고 자료

- [제목](URL)
- [제목](URL)
```

## 작성 기준

- 개념 수: 데일리 배움 카드 수와 동일하게 (2-4개)
- 각 개념은 반드시 "내 경험에서 시작"해야 한다 -- 교과서 정의로 시작하지 않는다
- 공식 문서 링크는 개념당 최소 1개
- "정리" 표는 오늘 배운 판단 기준을 한눈에 보여주는 용도
- "더 알아볼 것"은 데일리의 "추가 학습 질의"를 일반화한 버전
- 이모지를 쓰지 않는다
